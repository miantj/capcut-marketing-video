# capcut-cli 草稿与导出可靠性

## 能力边界

以实际安装版本为准检查 CLI 描述或源码。已观察到的 capcut-cli 0.22.0 行为仅作为需要复核的例子：

- `render` 是 FFmpeg 代理预览，不是剪映原生引擎。它可能只合成主视频轨、简化文字，并忽略字体、关键帧、装饰、混合及源视频声音。`--scale 1` 只提高像素尺寸，不解决渲染保真度。
- `export --batch` 是实验性 GUI 自动化。返回 `queued` 可能仅代表点击了导出菜单；应确认具体项目、导出结果文件和完成状态。不要拿全草稿库批量试运行；只将目标项目放入隔离队列。
- `sync-timelines` 可能以旧 `draft_content.json` 覆盖较新 `draft_info.json`；必须先看只读计划。发现 `canonical_stale` 时不强制写回。
- `--help` 不一定被子命令正确解析；使用 `describe` 或本地命令文档核实语法。

## 建立和校准草稿

先在独立工作目录编译，保留原素材，派生文件另存。优先使用相对工作目录的组织方式和当前工具支持的打包/重链接能力；引用应能解析到所交付草稿的素材目录。需要将项目加入剪映库时，确认真实库路径、注册行为和应用保存状态，只注册目标项目。

草稿文字常同时含 `font_size`、JSON 编码 `content.styles[].size`、字体路径/ID、文本段 `clip.scale`、关键帧和位置。最终显示受这些因素共同影响：

- 先检查基础字号、样式区间、片段缩放和关键帧；不能仅改某个字段便宣布字号已修复。
- 不直接套用 ASS 像素字号，不使用未经验证的 `剪映字号×2` 或固定 7.5–11 范围。
- 先生成 3–5 秒含长中文行的校准片段，并在目标剪映版本核对；确认后再扩展全部字幕。
- 样式使用范围索引时按当前 CLI 文档执行；JS UTF-16 索引不等于 Unicode 码点数量，emoji 尤其容易出错。
- 没有原生预览时，只能说明参数映射是估计；不要借 `lint` 结果证明效果一致。

## 读取用户二次编辑后的版本

执行本 skill 的只读检查脚本：

```bash
python3 <本skill目录>/scripts/inspect_inputs.py --draft /绝对路径/草稿目录
```

脚本枚举候选、mtime、哈希及差异，只报告信息，不自动选择或同步。结合 `capcut diagnose` 和实际内容判断：

1. 找准用户编辑的项目，核对项目 ID、文案、媒体及最新修改；不是永远读取某个固定文件名。
2. 比较 `draft_content.json`、`draft_info.json`、`template-2.tmp` 及版本相关的嵌套时间轴。mtime 新是线索；同 ID、相互印证的内容及用户可见修改更重要。无法确定选哪个时请用户指出项目，保留原始候选。
3. 检查字体、文本样式、缩放、位置、动画、源入出点、音量和画面处理；只比较新增轨道或时长不足以判断“没有编辑”。
4. 确定候选和哈希后，执行 `scripts/snapshot_draft.py --source <候选绝对路径> --expected-sha256 <本轮检查的SHA-256> --out <独立快照目录>`。来源改变会报错，须重新检查；工具不选版本、不复制媒体、不注册项目。用快照作为后续渲染输入，路径转换仅作用于另存的派生文件。不要为了导出覆写整个用户项目或关闭仍在编辑的应用。
5. 路径可能形如 `##_draftpath_placeholder_<id>_##/assets/...`。仅在派生快照里将确认属于本项目的占位符解析到真实素材目录，并检查文件存在。不要在桌面创建奇怪占位符软链接掩盖解析问题。
6. 已有导出流程失败时保留用户最新草稿，回到能力检查；不能改用历史 ASS 或旧视频冒充成功。

## 导出选择

只导出时不重做文案、字幕或动画。需要修改时从已确认快照建立独立项目，通过当前 CLI 的克隆/模板机制生成唯一项目身份并重链接素材；不得把相同 ID 的快照直接注册为新项目。按用户请求修改指定片段，比较修改前后文本、字体、位置、缩放、关键帧、剪切和音频，不把镜像同步当作创作修改。

选择候选后记录实际存在的用户可见的最新变化（只改一处就记录一处），作为输出验收点。例如“首句字体改为 X，第二句缩小并下移”。如果输出不包含这些变化，就不能称为用户编辑版。

目标是用户在剪映看到的效果：优先剪映原生导出。若自动化只支持旧时间轴，先解决目标项目打开方式，不能误开旧版本。原生导出失败时记录实际报错，区分素材缺失、字体不可用、权限、版本兼容和会员限制，不凭猜测归因。

当只能做外部渲染时：

- 列出本草稿使用的功能与外部渲染器支持范围。用户要求完全相同且存在未支持特性时，报告具体阻碍；不要声称能保证一致。
- 用户本轮或既有授权已接受近似预览后，按其可接受的差异直接渲染，不重复确认。字体、布局或动画替换须记录差异；替代渲染仍按 SKILL.md 的样式完成检查落实字体、进出场、花字及气泡。
- 外部渲染必须读取选定的最新快照；保留源剪切、变速、裁切、旋转、文本分行、分段颜色、位置、缩放和音频映射。未实现的项要公开说明。
- 不擅自复制剪映缓存的付费字体或效果到外部渲染器来绕过导出限制。可选方案为取得相应授权、用户同意的免费替代，或在基础功能内重做效果；字体已下载不代表获准使用。
- 有视频音轨不代表导出命令自动包含它。明确映射目标配音、原声和 BGM，检查混音和原文逐句同步。

## 交付来源核对

核对输出创建时间、实际媒体参数及几处用户最新修改。保留 `delivery.json` 中的来源快照哈希和实际渲染方式；输出名字避免混淆“原生导出”和“近似预览”。如果任务被工具/应用阻断，准确说明阻断点，交付已完成的草稿和诊断，不能交付无关旧文件充数。

## 草稿与成片文字一致性

新制作的MP4与原生草稿应从同一份样式数据生成：字体路径/名称、bold、填充色、各层alpha、描边颜色/宽度、阴影、分行、位置、时长和层级。字体未指定会被剪映替换为默认字体；只传颜色和字号不足以还原效果。含背景底板时为文字设置明确高于底板的显示层级，检查原生保存是否重新排序。并行显示的品牌/CTA放不同文本轨，不能用自动修复去裁短它们。

用户反映发浅时，区分色值、字体粗细、填充/片段透明度及alpha关键帧、描边和底板遮挡，不预设一定是颜色错误。先修复设置并在原生界面检查阅读停留段；如果不能进行原生预览，交付只能标注“设置已修复，原生显示待核对”，不能称两版完全一致。已知长标题不应使用lint --fix默认7秒截断；以实际阶段结束时间核对覆盖。

使用应用保存后的草稿作为来源时，其路径可能已变成draftpath占位符；在新副本中按已核实的assets归属解析，逐文件验证存在，再注册。不要把旧项目的占位符留给新项目。

## 字号校准与同源导出（本次缺陷修复要求）

ASS像素字号、原生font_size和富文本styles[].size不是同一单位。此前把原生32与外部69–76像素并列使用而未校准，导致用户在剪映看到与预览不同的字大小。不要把这些数字当成换算表，也不要按用户“大小不一样”猜测应该放大或缩小。

1. 选定已保存的最新时间轴，核对font_path、styles[].font、font_size、styles[].size、clip.scale及影响缩放的关键帧，保留用户改动。
2. 在动画已结束、文字完整停留的同一时刻测量原生预览；将预览画布坐标归一到成片尺寸，比对同一行可见字形包围盒、行距和边距。不要用带编辑框的窗口尺寸或处于入场缩放中间态的截图计算。检查短句、最长句和CTA，不以某一帧通过推断全部通过。
3. 在隔离副本定向调整，不扩大、缩小已烧录的整个视频来修字幕。修改后重开/刷新目标草稿，原生预览再次测量，并保持足够阅读停留。
4. 从这份草稿原生导出MP4，核对导出帧与原生预览；记录草稿哈希、时间点、文字bbox、画布尺寸、应用版本和通过/未通过状态。没有原生画面证据就保持pending，不生成虚假通过记录。

动画时长使用用户最新值：当前默认入场0.5秒、出场0.5秒，修改out时同步start=片段时长-500000微秒；保留已选的波浪弹入/缩小等资源。不要遗漏气泡文字或用新关键帧重复叠加同名效果。

若macOS提示“osascript不允许辅助访问”，这是系统辅助功能权限限制；说明需要用户在系统设置的隐私与安全性/辅助功能中为当前执行宿主授权。未经授权不尝试绕过；用户提供同帧原生预览和参考导出也可用于测量，但不能因此声称已自动原生导出。


## 原生样片发现的问题处理

用户提供原生导出后，先记录该文件哈希、项目名与来源时间轴；不同试调项目不能混作同一版本。以这份原生文件直接展示本次导出，不再次用外部字幕重做。

气泡为透明全画布图片时，图片中的气泡坐标已确定；叠加片段transform会再次移动它。按图片实际内容位置与文字中心校准，核对底图render_index低于气泡文字，避免位置修正后反而盖住文字。

实测字号比例仅适用于此次字体、样式、画布和缩放组合，不写成通用换算常数。记录修改前证据和修改后待验证状态；旧原生导出只能支持校准依据，不能证明新草稿已通过。
