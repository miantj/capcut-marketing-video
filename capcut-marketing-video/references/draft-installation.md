# 本机草稿安装与首页缺失排查

先区分：导入MP4后不能分别改字/配音、首页不显示草稿、打开报素材丢失。MP4是合成结果，应从首页打开多轨草稿；ZIP是备份包，不是自动安装器。

create链优先直接运行 `workflow.py install <run_dir> --store <实际库>`；它执行下面的结构步骤。已有工程编辑、原生版本兼容或恢复失败现场才按下面流程处理，保留实际命令和检查结果。

## 安装到用户实际使用的草稿库

1. 用doctor、应用配置、现有已知项目和索引确定实际库。不能仅凭目录存在认定用户在用它；剪映/Jianying与CapCut可能有不同库。
2. 查看目标ID/名称是否已存在；若已存在先核对最新内容，禁止用交付旧副本覆盖用户编辑。首次安装可以复制独立生成的草稿；若两个项目要同时保留则经CLI创建新的项目身份。保留完整本地assets，检查所有视频/音频/图片路径。
3. 安装前备份将修改的索引；新目标目录必须不存在。复制后只重定位该项目内部引用，并修正draft_fold_path、draft_root_path、draft_json_file、封面路径与名称。不得全库替换字符串。
4. 在目标草稿路径执行 `capcut register <目标> --materials --drafts <真实库>` 查看计划。检查返回的project_dir、store_root、targets确实属于真实库；计划无误后--apply。不要仅在桌面父目录生成root_meta_info.json。不要盲目同步不同名字的索引，依据实际版本与当前已知项目判断。
5. 重新从磁盘读真实索引，核对项目ID唯一、名称正确、不隐藏、tm_draft_removed=0、目标路径存在、素材已注册。运行下面的只读检查及lint/diagnose。素材路径应指向安装副本，不能依赖临时工作区。
6. 有可用原生UI工具时检查首页条目、打开时间轴、选择文字和音频轨可编辑且无重定位提示。没有UI能力时报告“已安装并通过索引/路径检查，尚未核对原生界面”；提示用户保存当前工作后返回首页或重启刷新，不强制关闭应用。

```bash
python3 <skill>/scripts/check_installed_draft.py --draft <已安装项目> --store <已确认真实库>
```

该脚本只验证声明结构和路径，不确认应用实际采用哪个库、原生显示/编辑能力或特效兼容。将真实库核对证据和UI验证状态另记入交付记录。手机竖屏与手机版草稿兼容是两个问题，未测试移动端导入时不能声称手机也能编辑。

## 交付

给出首页准确项目名、已安装目录、视频和自包含备份。打包排除历史备份和临时文件，不把工作区root索引作为用户应覆盖的系统索引。移动草稿后重新安装与重定位，不引导用户把MP4或ZIP当项目直接导入。
